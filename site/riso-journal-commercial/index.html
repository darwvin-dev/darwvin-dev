Riso Journal Commercial Privacy Policy

Developer: darwvin-dev · Last updated: 2026-09-07

This policy covers the paid/commercial Riso Journal build that uses Google Play Billing for the optional one-time full_unlock product.

Local content

Riso Journal stores the selected palette and wallpaper composition, three task strings and completion state, one short note, setup state, and a local Riso Full entitlement flag in app-local storage.

Riso does not upload task text, note text, wallpaper choices, or launcher guidance data to a developer-operated server.

Google Play Billing

The commercial build uses Google Play Billing for the one-time Riso Full purchase. Google Play handles payment credentials. Riso Journal does not request or receive the user's raw payment-card number.

The Billing Library can provide purchase-related information needed to operate the entitlement, including product ID, purchase state, purchase token or purchase-record metadata, and acknowledgement state.

The current commercial V1 uses this purchase information on-device. It does not transmit purchase tokens to a developer-operated purchase-verification backend.

Google Play independently processes purchase and payment information under Google's own terms and privacy policies.

Other services and permissions

The current commercial build has no Riso account, advertising SDK, remote analytics SDK, remote crash-reporting SDK, developer cloud backend, location permission, contacts permission, microphone permission, photo/media permission, SMS permission, call-log permission, or broad package-query permission.

Launcher visibility

The app declares narrow visibility for the current Android HOME launcher so it can display launcher-specific setup guidance. It does not request QUERY_ALL_PACKAGES.

Wallpaper files

When the user asks to apply a wallpaper, Riso Journal creates a temporary PNG in app cache and grants Android's wallpaper UI temporary read access through a private FileProvider path. Older generated Riso wallpaper cache files are removed when a new preview is prepared.

Backups and device transfer

Android app backup is disabled. Explicit backup rules exclude Riso app files, databases, and shared preferences from cloud backup and device-to-device transfer.

Retention and deletion

Local Riso data remains until the user changes it, uses Reset Riso Settings, clears Android app storage, or uninstalls the app. A wallpaper already applied by Android remains the system wallpaper until the user changes it.

Riso has no account system and therefore no remote Riso account record to delete.

Purchase verification scope

The first low-value offline commercial release intentionally uses client-side Play ownership/state checks rather than a developer purchase-verification backend. This is a weaker anti-tampering model than secure server verification and is accepted specifically for the offline V1 scope.

If a future release adds a purchase-verification backend, accounts, cloud sync, remote premium content, analytics, ads, or other data handling, this policy will be updated before that build is distributed.
